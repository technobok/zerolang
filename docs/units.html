1. Units

A program is built from units. A unit is a namespace of definitions: constants, data blocks, types, functions and other units. Every source file is one unit, named by its file name without the extension -- geom.z is the unit geom -- and a unit written inside another (inner: unit { ... }) is an inline unit, an ordinary definition of the unit around it. A unit has no initialisation and is never imported: a name that reaches it loads it, and only what the program reaches is checked and emitted.

A unit's name is written in lowercase ASCII letters, digits and _, so that it is the same file name on every filesystem; a file named otherwise is not found as a unit.

2. Finding a unit

A name the program writes is resolved outward: the unit it is written in, each unit enclosing that one up to the file unit, then core. A file unit is found on the source roots -- the project's sourceDirs when a project.z names them, else the --src directories, else the current directory -- the first root searched first, and then in the standard library (--system). See zc (Projects) for project.z and its settings.

A file unit may keep implementation subunits in a directory of its own name: geom.z beside geom/ whose files are geom's subunits. A name written in geom looks in geom/ before the roots, so a subunit can shadow a unit of the same name elsewhere -- but only within geom. A subunit sees its parents as every unit does: it resolves outward through them.

3. Visibility

A unit's top-level definitions are public by default. A public: unit { ... } block restricts the unit's surface to what it lists; an unlisted definition is private and unreachable from another unit (E0101). An entry may rename what it exposes: :name exposes name as itself, alias: internal exposes internal as alias. An implementation subunit is private to its parent unless the parent's public: block lists it (public: unit { :impl }), which is also what loads it for others. Privacy governs who may reach into a unit; it says nothing about what the unit sees. See the Visibility section of the language specification.

4. Generic units

A unit may be generic over types or values. An inline unit declares its parameters in its as block (mathops: unit as { t: anyval.generic ... }); a file unit declares them at the top of the file, beside its other definitions (t: anyval.generic in cells.z). An instance is named by applying the unit to its arguments -- (cells t: i64), at unit level ic: (cells t: i64) -- and is a namespace, not a value: the same arguments name the same instance wherever they are written, and a type the unit declares is named through it (ic.Cell). See the Generic Units section of the specification.

5. Toolchain requirements

A require: block states what a unit needs from the host toolchain: require: unit { library: "quadmath" }. It is an ordinary inline unit with a schema layered over it: every entry must be a key the compiler consumes -- today only library:, a compile-time string naming a link library -- and the block must declare at least one (E0038). A requirement applies only when its unit is reached: a program that never uses the unit does not link the library.

6. The project unit z

Every program can read the generated unit z: z.build describes the build (the target's architecture and operating system, the triple) and z.project the project's own project.z settings, such as z.project.sourceDirs. It is served by the compiler, with a copy on disk under .zerolang/ for people and editors. See the z unit.

7. Runtime-backed stdlib units

The core stdlib units (system, core, collections, io, os, cli) are declaration surfaces for the C runtime: their types and is native functions are implemented under src/runtime, while bodied free functions in them are ordinary compiled zerolang (demand-gated). Type methods there cannot carry .z bodies. Details in the compiler doc's "Runtime-backed stdlib units" section.

The fixtures that pin these rules: hidden_subunit.z and subunit_depth.z (subunits, and a subunit's own subunit), public_subunit_listed.z (a subunit a public: block lists), subunit_parent_read.z and subunit_grandparent_read.z (a subunit reading outward), gfu_cells.z with generic_file_unit_types.z (a generic file unit), all under tests/fixtures/emitc_corpus.
