1. Overview

The declarations themselves live in lib/system/cli.z, which is the one place they are written. Every definition, field, arm, generic parameter and own-line parameter there carries its own doc comment, and zls surfaces each on hover; the corpus runner ratchets that coverage under make ci. This page is the prose and the worked examples -- read it for how the unit is meant to be used, and the source for the exact surface.

The cli unit is a small argv parser. Users declare a Spec (flags, options, positional arguments, each with help text), hand it to cli.parse with the argv list, and get back a Parsed handle with accessor methods. Help text is auto-generated from the spec.

Accessed via qualified names only -- cli.Spec.create, cli.parse ...; no unqualified re-export.

Grammar supported (GNU-getopt conventions).

  --name              long flag
  --name value        long option (value is the next argv token)
  --name=value        long option (embedded value)
  -x                  short flag
  -o value            short option
  -xvf                bundled short flags
  -vo value           bundle ending in a short option (value is the next token)
  -ofile              short option with embedded value
  --                  end-of-options; rest go to extraArgs
  -                   positional (stdin convention)

Design principles.

  • Register-then-parse. Setup is a sequence of declarative calls against a mutable spec; the whole parse is one function call. No stateful builder objects to juggle
  • One argv shape. cli.parse takes the whole vector as os.args returns it and reads it from position first, which is 1 when not given: position 0 is the program name. A program that reads its command at position 1 itself gives first: 2
  • Fail fast, fail whole. Parse either returns a fully validated Parsed or an early err with a descriptive payload. No partial results; no mutable error list
  • Help is a property of the Spec. cli.helpText takes the same spec that parsed the args, so the rendered usage never drifts from the registered behaviour
  • One wording for an error. cli.errorText gives the sentence for a CliError, so every program that uses the unit refuses a command line in the same words

Not shipped yet.

  • Long-option prefix abbreviation (--ver for --verbose): v1 is exact-match only

2. Index

Registration types

  • FlagDef -- class { name: String shortName: String help: String }
  • OptionDef -- class { name: String shortName: String help: String required: bool repeats: bool }
  • PositionalDef -- class { name: String help: String required: bool }

Spec + Parsed handle

  • Spec -- class { programName: String summary: String flags: ... options: ... positionals: ... stopAtOperand: false }
  • Parsed -- class { flagSet ... optionValues ... repeatValues ... positionalValues ... extraArgs ... extraOperands: u64 }
  • OptionValue -- class { name: String value: String }

Errors

  • CliError -- union { unknownFlag: String ... unexpectedArg: String }

Registration

  • cli.addFlag -- function {spec: Spec.borrow name: String.take shortName: String.take help: String.take}
  • cli.addOption -- function {spec: Spec.borrow name: String.take shortName: String.take help: String.take required: bool repeats: false}
  • cli.addPositional -- function {spec: Spec.borrow name: String.take help: String.take required: bool}

Parse + render

  • cli.parse -- function {spec: Spec.view args: (List String).take first: 1.u64} out (Result Parsed E: CliError)
  • cli.helpText -- function {spec: Spec.view} out String
  • cli.errorText -- function {spec: Spec.view e: CliError.view} out String

3. flagdef

One registered long flag plus optional short alias. Class because String fields are reftypes and valtypes cannot hold reftypes.

Users rarely construct FlagDef directly -- the cli.addFlag helper does it for you.

4. optiondef

One registered option (long + optional short alias), with a required-presence flag and a repeats flag. Constructed via cli.addOption.

5. positionaldef

One registered positional slot, named for lookup. Constructed via cli.addPositional.

6. spec

Parser registration state. Built incrementally via cli.Spec.create then the cli.addFlag / cli.addOption / cli.addPositional helpers. All string fields are owned; list fields hold the registered defs in insertion order (which is also help-text output order).

  sp: cli.Spec.create programName: "zgrep".string summary: "search files for a pattern".string

The three list fields are initialised empty.

#~"stopAtOperand" is for a program that starts another one and hands it arguments. Set it to true, and the first operand past the declared positionals ends the reading: that token and every token after it go to extraArgs as written, whatever they look like. A flag written before that operand is still read. -- ends the reading as it always does.

main: function is {
    sp: cli.Spec.create programName: "tool".string summary: "".string
    sp.stopAtOperand = true
    cli.addFlag spec: sp name: "--verbose".string shortName: "-v".string help: "".string
    cli.addPositional spec: sp name: "unit".string help: "".string required: true
    args: List String
    for each t: ("tool hello -v one --two -v".split sep: " ") loop args.append t.string
    pr: cli.parse spec: sp :args
    match (
        pr
    ) case ok then {
        print "verbose \{pr.hasFlag name: "--verbose"}"
        for each x: pr.extraArgs loop print "extra \{x}"
    } case err then {
        print (cli.errorText spec: sp e: pr)
    }
}
verbose true
extra one
extra --two
extra -v

7. parsed

Successful parse result. Opaque; inspect via the accessor methods.

Accessors.

  • hasFlag name -- was this flag present? Look up by the registered long name (e.g. --verbose), not the short alias
  • option name -- value of this option, or Option.none if absent
  • positional name -- value of this positional, or Option.none if absent
  • optionAll name -- every value kept for this option, in the order written: all of them for an option declared repeats: true, the last for any other. An empty list if absent
  • given name -- was this name written at all, as a flag, as an option or as a positional? It tells a value the command line gave from a default the program fills in

#~"extraArgs" holds every token beyond the declared positionals, then every token after a bare -- (the end-of-options terminator), in order. There is no accessor -- read the field directly.

#~"extraOperands" is how many of extraArgs are operands beyond the declared positionals. The tokens from that index on were not read: they followed --, or the first of them ended the reading under stopAtOperand. A program that hands the tokens after -- to another program, and takes no operand of its own before it, reads the two parts apart:

main: function is {
    sp: cli.Spec.create programName: "tool".string summary: "".string
    cli.addPositional spec: sp name: "unit".string help: "".string required: true
    args: List String
    for each t: ("tool hello stray -- one --two".split sep: " ") loop args.append t.string
    pr: cli.parse spec: sp :args
    match (
        pr
    ) case ok then {
        i: 0.u64
        for each x: pr.extraArgs loop {
            if i < pr.extraOperands then print "operand \{x}" else print "passed on \{x}"
            i = i + 1
        }
    } case err then {
        print (cli.errorText spec: sp e: pr)
    }
}
operand stray
passed on one
passed on --two

Ownership. option / positional each return a fresh Option String -- scope-exit frees the boxed string. optionAll returns a fresh List String.

8. optionvalue

One value written for an option that repeats: the option's long name and the value. Parsed.repeatValues holds them in the order written; read them through optionAll.

9. clierror

Parse-time failures. Each arm carries a descriptive String so callers can compose diagnostics or print the offending token directly. Union (not variant) because every arm carries a reftype payload.

Arms.

  • unknownFlag -- an argv token starts with - or -- but no registered flag / option matches, or a bundle such as -vq holds a letter that none does. Payload is the offending token
  • missingValue -- an option's expected value was absent (e.g. --output, or a bundle ending in one such as -vo, with no following token). Payload is the token as given (--output, -o or -vo)
  • missingRequired -- an option or positional marked required: true had no value. Payload is the name
  • unexpectedArg -- a flag given an embedded value (--verbose=1); flags take none. Payload is the token

10. add_flag

Register a flag on Spec. The spec is borrowed so mutations propagate to the caller's spec. Name conventions: pass the full long form (--verbose) and optional short alias (-v); help text is free-form.

  (
      cli.addFlag
      spec: sp
      name: "--verbose".string
      shortName: "-v".string
      help: "verbose output".string
  )

11. add_option

Register a value-carrying option on Spec. required: true causes a missingRequired error from parse when the option is absent. repeats: true keeps every value the command line gives, for optionAll; it is false when not given, and option answers the last value either way.

  (
      cli.addOption
      spec: sp
      name: "--output".string
      shortName: "-o".string
      help: "out file".string
      required: false
  )
  (
      cli.addOption
      spec: sp
      name: "--include".string
      shortName: "-I".string
      help: "a directory to search; may be given again".string
      required: false
      repeats: true
  )

12. add_positional

Register a positional slot on Spec. Positionals are consumed in registration order as argv tokens arrive.

  cli.addPositional spec: sp name: "pattern".string help: "regex".string required: true
  cli.addPositional spec: sp name: "file".string help: "input".string required: true

13. parse

Parse args against the registered Spec. args is the whole argument vector as os.args returns it; position 0, the program name, is skipped. Typical call site:

  pr: cli.parse spec: sp args: os.args
  match (
      pr
  ) case ok then {
      v: pr.hasFlag name: "--verbose"
      o: pr.option name: "--output"
      pat: pr.positional name: "pattern"
      print "verbose=\{v}"
  } case err then {
      io.eprintln (cli.helpText spec: sp)
  }

Accessors look up by the registered long name, not the short alias -- use the long name throughout for both registration and lookup.

A program with commands reads its command at position 1 itself, picks that command's spec, and gives first: 2 so that parse reads what follows the command.

main: function is {
    sp: cli.Spec.create programName: "tool".string summary: "".string
    (
        cli.addOption
        spec: sp
        name: "--src".string
        shortName: "".string
        help: "".string
        required: false
        repeats: true
    )
    args: List String
    for each t: ("tool build --src a --src=b main".split sep: " ") loop args.append t.string
    pr: cli.parse spec: sp :args first: 2
    match (
        pr
    ) case ok then {
        for each d: (pr.optionAll name: "--src") loop print "src \{d}"
        for each x: pr.extraArgs loop print "extra \{x}"
    } case err then {
        print (cli.errorText spec: sp e: pr)
    }
}
src a
src b
extra main

Ownership. parse consumes args (the argument list may be freed during parsing). Callers who need to retain the argv vector should pass a copy. Spec is only read -- the same spec can parse multiple argv vectors.

14. help_text

Render the usage + help block from the spec. Returns a freshly-allocated String.

  usage: zgrep [options] <pattern> <file>

  zgrep-style pattern matcher.

  Flags:
    -v, --verbose    verbose output

  Options:
    -o, --output    out file

  Positionals:
    pattern    regex
    file    input

Layout is deterministic: registration order is preserved.

15. error_text

The sentence that says a CliError to the person who wrote the command line. It starts with the spec's programName, is one line, and has no newline at its end.

ErrorSentence
unknownFlagtool: unknown option '--quiet'
missingValuetool: --output needs a value
missingRequiredtool: missing --level for an option, tool: missing <file> for a positional
unexpectedArgtool: --verbose takes no value

A program that has a help command appends its own pointer to it; errorText does not know that one exists.

main: function is {
    sp: cli.Spec.create programName: "tool".string summary: "".string
    cli.addPositional spec: sp name: "file".string help: "".string required: true
    args: List String
    args.append "tool".string
    pr: cli.parse spec: sp :args
    match (
        pr
    ) case ok then {
        print "ok"
    } case err then {
        io.eprintln "\{cli.errorText spec: sp e: pr}; `tool help` lists the options"
        print (cli.errorText spec: sp e: pr)
    }
}
tool: missing <file>
