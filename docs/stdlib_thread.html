1. Overview

The declarations live in lib/system/thread.z, each with its own doc comment; this page is the prose and the worked examples.

The thread unit runs work on its own operating-system thread. The work is a Task -- a class that declares it conforms (task: thread.Task) and has a call method. The task is moved to the thread when it starts, so nothing else can touch it while it runs, and join hands it back:

  # Counter -- counts on its own thread
  Counter: class {
      # how far it counted
      n: i64
  } as {
      task: thread.Task
      call: function {:this} is {
          i: 0.i64
          for i < 1000 loop {
              this.n = this.n + 1
              i = i + 1
          }
      }
  }

  main: function is {
      h: thread.spawn task: (Counter n: 0) name: "counter"
      done: h.join
      print "counted \{done.n}"
  }

There are no shared mutable variables to protect by hand: what a thread uses is either moved to it or borrowed by it, and the lock model below keeps the owner away from what a running task borrows. The sync unit (Mutex, Channel and the rest) is for data that really is shared.

2. Tasks and handles

  • Task -- protocol { call: function {:this} }. The thread's body; it runs once. A task is any class that declares task: thread.Task.
  • spawn -- function {task: T.take name: "" stackSize: 0} outx (JoinHandle T). Starts the task. name labels the thread for debuggers and top (15 bytes are kept); a stackSize of 0 is the default, 8 MiB -- the main thread's usual size, so a program that recurses deeply on main recurses as deeply on a thread.
  • JoinHandle -- the started thread. join waits for it and answers the task; isFinished says whether join would wait; id is the thread's id as the operating system numbers it (0 once joined). Destroying a handle that was never joined joins it: a scope cannot end while a thread it started still uses what the scope owns.
  • spawnDetached -- the same start with no handle: the thread runs to its end on its own and frees its task. The program may end while it still runs.
  • yieldNow -- let another thread run.
  • running -- how many threads the program started that have not finished. A thread leaves the count after its task is destroyed, so a program that must not end before its detached tasks waits for 0: for thread.running > 0 loop thread.yieldNow.

Read bare, a value whose type has a call is called -- a task is an iterator-shaped value in that respect -- so a task held in a variable is passed with .take: thread.spawn task: t.take.

3. Borrowing tasks

A task may hold borrows -- a .borrow field into data its owner keeps. The handle carries the task's locks (spawn is outx), so while the handle lives, or the task join answered, the owner can neither write nor read nor drop what the task borrows, and two running tasks cannot borrow one source:

  # Summer -- sums a list its owner lends it
  Summer: class {
      # the borrowed input
      xs: (ListVal i64).borrow
      # the answer
      total: i64
  } as {
      task: thread.Task
      call: function {:this} is {
          for each x: this.xs loop this.total = this.total + x
      }
  }

  main: function is {
      xs: ListVal i64
      xs.append 1
      xs.append 2
      {
          h: thread.spawn task: (Summer :xs total: 0)
          s: h.join
          print "summed \{s.total}"
      }
      xs.append 3
      print "the owner writes again: \{xs.length}"
  }

Inside the inner block xs.append 3 is refused (exclusive lock held by 'h'); after it, the lock is gone. join is {:this} outx T: the task it answers keeps the handle locked, which is what keeps the task's borrows alive.

spawnDetached is out, not outx: nothing would keep what a detached task borrows alive, so a task holding a borrow is refused there.

4. What may cross to a thread

A task moves to its thread whole, with everything it holds. A type that conforms to thread.ThreadBound -- a marker protocol, with no methods -- never makes that move: a value of it is refused as a task, and as anything a task holds at any depth, whether it is owned, viewed or borrowed, or sits in a list inside another class. The lock guards (sync.MutexGuard, sync.ReadGuard, sync.WriteGuard) are the stdlib's: a guard unlocks on the thread that locked, and unlocked on another the lock is undefined. Lock on the new thread instead -- the task holds the Mutex, by .view, and takes the guard itself:

  # Waiter -- waits on a guard its owner locked
  Waiter: class {
      # the guard, locked on the owner's thread
      g: sync.MutexGuard (ListVal i64)
  } as {
      task: thread.Task
      call: function {:this} is {
          print "\{this.g.value.length}"
      }
  }

  main: function is {
      m: (sync.Mutex (ListVal i64)).create value: ListVal i64
      g: m.lock
      h: thread.spawn task: (Waiter :g)
      h.join
  }

Refused: "Cannot hand 'Waiter' to another thread with #~"thread.spawn": it holds 'MutexGuard', and a thread.ThreadBound value never leaves the thread that made it".

5. Panics

A panic on any thread ends the whole program, with status 1: the panic is reported once, however many threads panic, and the process ends without running exit handlers under the other threads' feet. There is no catching it and no poisoned state to recover.

6. Building

A program that starts a thread links pthread (the zlink: line of its C says so), and its C differs from a program that does not only where threads need it -- the panic above. Programs that start no thread compile exactly as they did. The C layer is src/runtime/natives/_Z_THREAD_SHIM.inc: pthreads on Linux and other POSIX systems, Win32 threads on Windows.
