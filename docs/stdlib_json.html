1. Overview

The json unit is a JSON (RFC 8259) value tree, parser, and serializer. The tree is a reftype tagged sum (Value) mirroring the AST's union-of-carriers shape: scalars ride in the arm payload, arrays and objects in carrier classes (Arr, Obj). Objects remember key insertion order, so serialization is deterministic; lookup stays O(1). Integers and floats are separate arms, so i64 values (protocol ids, offsets) round-trip exactly.

Accessed via qualified names only -- json.parse ..., json.Value.intval ...; there is no unqualified re-export.

The #~"(Box T)" arm rule, showcased. A union's arms hold reftypes; a valtype arm is spelled (Box T) and collapses to its element. Value is the standard library's showcase of the rule: the boolean / intval / floatval arms are declared (Box bool) / (Box i64) / (Box f64), yet construction takes the bare value and a match arm narrows to the bare element -- no Box appears in user code:

  v: (json.Value.intval 42)   # construction takes the bare i64
  match (v)
  case intval then print "\{v}"   # v narrows to the bare i64
  else print "not an int"

Reading a tree. Element and member reads inside the tree are borrows, which user code cannot return -- so the path accessors (at and its typed wrappers) surface the terminal value as scalars in a Found: the kind arm plus the matching payload slot. Strings are copied out; structure (array / object) is reported by kind and length, and is navigated in place by matching on the tree at the use site.

3. value

  Value: union {
      nul:      null
      boolean:  (Box bool)
      intval:   (Box i64)
      floatval: (Box f64)
      text:     String
      array:    Arr
      object:   Obj
  }

A JSON value: a tagged sum of null / bool / int / float / string / array / object. The scalar arms follow the (Box T) arm rule (a union holds reftypes; the Box argument collapses to its element), text holds an owned String, and the two structured arms hold the Arr and Obj carrier classes. Integers and floats are deliberately separate arms: a JSON number without . or an exponent parses to intval and serializes back digit-for-digit, so 64-bit ids survive a round trip that a single f64 arm would corrupt.

Construction goes through the arm accessors; the collapsed arms take the bare scalar:

  a: json.Value.nul
  b: (json.Value.boolean true)
  n: (json.Value.intval 42)
  t: (json.Value.text "hi".string)

Matching narrows the subject to the arm's element type -- the bare scalar for the collapsed arms, the carrier class for array / object:

  match (v)
  case intval then print "int \{v}"          # v is the bare i64
  case text   then print "text \{v}"         # v is the String payload
  case array  then print "\{v.items.length} elements"
  case nul    then print "null"
  else print "something else"

4. arr

  Arr: class {
      items: (List Value)
  }

A JSON array -- an ordered list of Values. The items field is public: append, index and iterate it directly with the ./stdlib_collections.htmlList surface.

  a: (json.Arr items: (List json.Value))
  a.items.append (json.Value.intval 1)
  a.items.append (json.Value.intval 2)
  v: (json.Value.array a)

5. obj

  Obj: class {
      entries: (Map String value: Value)
      keys:    (List String)
  } as {
      set: function {:this key: String.take value: Value.take}
      has: function {:this key: StringView} out bool
  }

A JSON object -- string-keyed Values kept in insertion order. entries gives O(1) lookup; keys remembers first insertion order, which is the order serialize emits.

  • set key: value: -- insert or replace key. A first insertion records the key in keys; a replacement keeps the original position
  • has key: -- whether key is present, looked up by view
  o: (json.Obj entries: (Map String value: json.Value) keys: (List String))
  o.set key: "answer".string value: (json.Value.intval 42)
  o.set key: "label".string  value: (json.Value.text "hi".string)
  root: (json.Value.object o)
  print (json.serialize v: root)   # {"answer":42,"label":"hi"}

6. jsonerror

  JsonError: class {
      at:  u64
      msg: String
  }

A parse failure: at is the byte offset into the input where the parser stopped; msg is a short description (unexpected character, expected ',' or '}', unterminated string, bad escape, unpaired surrogate, bad number, nesting too deep, trailing data, ...). Only the first failure is recorded.

7. parseresult

  ParseResult: union {
      err: JsonError
      ok:  Value
  }

The outcome of parsing JSON text: ok carries the root Value, err a JsonError. A dedicated union rather than a Result instantiation, matched the same way (falsy arm first).

8. foundkind

  foundkind: variant {
      missing:  null
      nul:      null
      boolean:  null
      intval:   null
      floatval: null
      text:     null
      array:    null
      object:   null
  }

Which value kind a path lookup landed on, or missing when the path does not resolve. One arm per Value arm plus missing; all payloads are null, so a foundkind is a plain inline discriminator.

9. found

  Found: class {
      kind: foundkind
      b:    bool
      i:    i64
      f:    f64
      s:    String
      n:    u64
  }

A scalar path-lookup result: the kind plus the matching payload slot. Only the slot named by kind is meaningful -- b for boolean, i for intval, f for floatval, s for text (an owned copy of the string), and n for array / object (the element count / key count). The other slots hold zero values.

Found exists because reads inside the tree are borrows that cannot leave the call chain; copying the terminal scalar out gives the caller an unencumbered value. Structure is reported by kind and length only -- navigate an array or object in place by matching on the tree.

10. parse

  parse: function {source: StringView} out ParseResult

Whole-input parse of source; trailing non-whitespace after the root value is an error. Any JSON value may be the root -- an object, array, string, number, boolean, or null.

  • Nesting is capped at 128 levels of arrays / objects (nesting too deep)
  • Strings handle the RFC 8259 escapes \", \\, \/, \b, \f, \n, \r, \t and \uXXXX, including surrogate pairs; an unpaired surrogate, a bad escape, or a raw control byte in a string is an error
  • Numbers without . or an exponent become intval and must fit i64 (overflow is a parse error); anything with . / e / E becomes floatval via f64 parsing
  • Duplicate keys follow Obj.set: the later value replaces the earlier one, at the key's original position
  pr: json.parse source: "[1, 2, 3]"
  match (pr)
  case ok then {
      n: json.arrayLength v: pr
      print "\{n} elements"
  }
  case err then print "parse error at byte \{pr.at}: \{pr.msg}"

11. serialize

  serialize: function {v: Value.view} out String

Serialize v to compact JSON text: no whitespace, object keys in insertion order, strings escaped per RFC 8259 (", \, backspace, form feed, newline, carriage return and tab as named escapes; other control bytes as \u00XX; multi-byte UTF-8 passed through verbatim). Returns a fresh owned String.

Because objects keep insertion order, parse --> serialize round-trips a document key-for-key, and building the same tree twice serializes to identical text.

12. at

  at: function {v: Value.view path: StringView} out Found

Walk path from v and describe the terminal: a /-separated sequence of segments, where a segment names an object key and a numeric segment indexes an array (params/textDocument/uri, tags/0). Returns a Found -- kind missing when any step fails to resolve (absent key, index out of range, or a scalar where structure was expected).

  r: json.at v: root path: "result/items/0/label"
  k: r.kind
  match (k)
  case text    then print "label: \{r.s}"
  case missing then print "no label"
  else print "unexpected kind"

The typed wrappers below cover the common cases; reach for at itself when you need the kind, or a length without matching on the tree.

13. describe_value

  describeValue: function {v: Value.view} out Found

One Value as a Found, with no path step: the kind arm plus the matching payload slot (string copied out; array / object reported as kind plus length in n).

14. text_at

  textAt: function {v: Value.view path: StringView} out (Option String)

The terminal string at path, as an owned copy. none when the path does not resolve or the terminal is not a string.

  nm: json.textAt v: root path: "name"
  match (nm)
  case some then print "name: \{nm}"
  case none then print "name missing"

15. int_at

  intAt: function {v: Value.view path: StringView} out (optionval i64)

The terminal integer at path. none when the path does not resolve or the terminal is not an intval (a float is not silently truncated).

16. bool_at

  boolAt: function {v: Value.view path: StringView} out (optionval bool)

The terminal boolean at path. none when the path does not resolve or the terminal is not a boolean.

17. has_at

  hasAt: function {v: Value.view path: StringView} out bool

Whether path resolves to any value at all -- of any kind, including null.

18. array_length

  arrayLength: function {v: Value.view} out u64

Element count of v, or 0 when v is not an array. Takes the value itself, not a path -- combine with a match on an array arm, or use at and read n.

19. found_missing

  foundMissing: function out Found

A Found marking "no such path": kind missing, every payload slot at its zero value. This is what at returns for an unresolved path; useful as a default when building your own lookups over a tree.

20. A worked example

Parse a small document, walk it with the path accessors, and serialize it back:

  src: "{\"name\": \"ada\", \"port\": 8080, \"tags\": [\"x\", \"y\"]}"
  pr: json.parse source: src
  match (pr)
  case ok then {
      nm: json.textAt v: pr path: "name"
      match (nm)
      case some then print "name: \{nm}"
      case none then print "name missing"

      pt: json.intAt v: pr path: "port"
      match (pt)
      case some then print "port: \{pt}"
      case none then print "port missing"

      t0: json.textAt v: pr path: "tags/0"
      match (t0)
      case some then print "first tag: \{t0}"
      case none then print "no tags"

      out: json.serialize v: pr
      print out       # {"name":"ada","port":8080,"tags":["x","y"]}
  }
  case err then print "parse error at byte \{pr.at}: \{pr.msg}"

Inside the case ok arm the bound name pr narrows to the root Value; inside case some each bound option narrows to its payload. The string literal is a StringView, which is exactly what parse takes.
