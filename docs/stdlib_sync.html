1. Overview

The declarations live in lib/system/sync.z, each with its own doc comment; this page is the prose and the worked examples.

The sync unit is for data that threads really do share. A thread's own work is moved to it or borrowed by it (see thread); what several threads use at once is a sync value, and each thread holds its own handle to it. An atomic, a Mutex, an RwLock, a Condvar and a Barrier are handles: x.share makes another handle to the same shared state, each task owns the one moved into it, and the state lives until the last handle ends. A thread changes the state through a borrow of its own handle -- locking, storing, notifying, waiting -- so a .view of a handle only reads (load an atomic, ask a channel's capacity). A guard keeps the handle it locked through: a second lock through one handle while the guard lives is refused, where it would wait for itself forever. A channel is two owned ends instead, each moved to the thread that uses it.

2. Atomics

  • AtomicI32, AtomicI64, AtomicU32, AtomicU64 -- names for Atomic t over each integer type every target updates in one instruction: load, store, exchange, compareExchange, fetchAdd and fetchSub. Arithmetic wraps.
  • AtomicBool -- load, store, exchange, compareExchange.
  • memoryorder -- relaxed, acquire, release, acqRel, seqCst, as C11 and Rust name them. Every operation takes order:, default seqCst -- the one to reach for; the weaker orders are for code that has proved it needs them. A load cannot release and a store cannot acquire: either panics.

exchange is C11's name for Rust's swap, which is a zerolang statement. compareExchange stores new only if the atomic holds current, and answers what it held -- so it stored exactly when the answer is current:

  # Adder -- adds to a counter it shares
  Adder: class {
      # its handle to the counter every Adder shares
      total: sync.AtomicI64
  } as {
      task: thread.Task null
      call: function {:this} is {
          i: 0.i64
          for i < 1000 loop {
              this.total.fetchAdd value: 1
              i = i + 1
          }
      }
  }

  main: function is {
      total: sync.AtomicI64.create value: 0
      {
          a: thread.spawn task: (Adder total: total.share)
          b: thread.spawn task: (Adder total: total.share)
      }
      print "total \{total.load}"
      seen: total.compareExchange current: 2000 new: 0
      print "it held \{seen}, now \{total.load}"
  }

3. Locks

  • Mutex T -- owns a value one thread at a time reaches. create value: moves the value in; lock waits for the lock and answers a MutexGuard, whose value is the Mutex's value to read and write. Destroying the guard unlocks.
  • RwLock T -- owns a value many threads may read at once, or one write: read answers a ReadGuard (its value is a view), write a WriteGuard (its value writes). A writer waits for every reader. Its readers run at once, so it conforms to thread.SharedReads, and one over a thread.Unshareable value (a sqlite connection) cannot reach another thread -- use a Mutex.

The value is reached only through a guard, so it is never touched unlocked, and the lock model keeps the rest straight: a guard keeps the handle it locked through (the handle can be neither dropped, moved nor locked again while one lives), value holds the guard for as long as what it answered lives, and a read guard's value cannot be written. T is a reference type (AnyRef); wrap a plain value in a class. A guard unlocks on the thread that locked, so every guard conforms to thread.ThreadBound: it never reaches another thread (see thread).

  # Filler -- appends to a list it shares
  Filler: class {
      # its handle to the list every Filler shares
      m: sync.Mutex (ListVal i64)
  } as {
      task: thread.Task null
      call: function {:this} is {
          i: 0.i64
          for i < 100 loop {
              g: this.m.lock
              g.value.append i
              i = i + 1
          }
      }
  }

  main: function is {
      m: (sync.Mutex (ListVal i64)).create value: ListVal i64
      {
          a: thread.spawn task: (Filler m: m.share)
          b: thread.spawn task: (Filler m: m.share)
      }
      g: m.lock
      print "\{g.value.length} appended"
  }

4. Waiting

  • Condvar -- where a thread waits for a condition another makes true. Holding a Mutex's guard, the waiter calls g.wait cond: cv: it unlocks while it waits and locks again before it returns. g.waitTimeout cond: cv ms: 50 gives up after the time and answers whether it did. The thread that changes the value under the lock calls notifyOne or notifyAll. A wait may return with nothing notified, so the waiter checks its condition in a loop.
  • Barrier -- create count: n; each wait returns once n threads have called it, and answers whether this thread is the round's leader (exactly one is). The barrier is then ready for the next round.
  # Slot -- a value and whether it is set
  Slot: class {
      # whether `value` is set
      ready: bool
      # the value
      value: i64
  }

  # Setter -- sets the slot, then wakes the waiter
  Setter: class {
      # its handle to the slot, under its lock
      m: sync.Mutex Slot
      # its handle to where the waiter waits
      cv: sync.Condvar
  } as {
      task: thread.Task null
      call: function {:this} is {
          {
              g: this.m.lock
              with s: g.value do {
                  s.value = 7
                  s.ready = true
              }
          }
          this.cv.notifyAll
      }
  }

  main: function is {
      m: (sync.Mutex Slot).create value: (Slot ready: false value: 0)
      cv: sync.Condvar.create
      h: thread.spawn task: (Setter m: m.share cv: cv.share)
      g: m.lock
      for g.value.ready.not loop g.wait cond: cv
      print "set to \{g.value.value}"
  }

5. Channels

A channel is two owned ends, each moved to the thread that uses it.

  • Receiver T -- the one reading end, which owns the channel. (sync.Receiver T).create capacity: n holds at most n values (0, the default, has no limit). receive waits for a value and answers it as an Option T; tryReceive answers none at once when nothing is waiting; for each x: rx walks the values as they come. A Receiver has no copy: a second reader is a second channel.
  • Sender T -- a sending end. rx.sender makes one and tx.copy another. send value: moves a value in, waiting while the channel is full, and answers whether the Receiver still lives: when it does not, the value is destroyed where it was sent.
  • ReceiverVal t / SenderVal t -- the same for a value type: values are copied in, and receive answers an optionval t.
  • close -- sync.close sender: tx.take ends a Sender before its scope does.

How a channel ends: when the last Sender is gone, receive drains what is left and then answers none, and for each stops. A Sender held by a task ends when the task does -- as its call returns -- so a parent that walks a Receiver stops once its producers have returned. A Sender the walking thread itself holds would keep the channel open forever: close it first (sync.close), or never make one there. When the Receiver ends first, what it never took is destroyed with it, and every later send answers false.

Each value goes to exactly one receiver, in the order sent. A value travels to another thread, so it may hold no borrow -- send refuses one, as every method refuses a lock-holding value (see Ownership, "Locks move with the value"). A channel of thread.ThreadBound values never reaches another thread at all: a task holding either end of it is refused where it is spawned. Two-way traffic is two channels: a request may carry a Sender for its own reply, an ordinary owned field. A channel with a capacity is bounded both ways: two threads each sending to the other's full channel before either receives wait for each other forever, so let one side receive before it sends, or leave a capacity of 0.

  # Producer -- sends numbered messages, then ends, and its Sender with it
  Producer: class {
      # where it sends
      tx: sync.Sender String
  } as {
      task: thread.Task null
      call: function {:this} is {
          i: 0.i64
          for i < 3 loop {
              this.tx.send value: "message \{i}"
              i = i + 1
          }
      }
  }

  main: function is {
      rx: (sync.Receiver String).create capacity: 1
      p: thread.spawn task: (Producer tx: rx.sender)
      for each got: rx loop print got
      print "the producer is done: \{rx.receive.none}"
  }

6. Building

A program that uses sync links pthread, like one that starts a thread; every class is written from a C template over the shim src/runtime/natives/_Z_THREAD_SHIM.inc (pthreads, or Win32 on Windows).
