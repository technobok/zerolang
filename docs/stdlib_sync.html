1. Overview

The declarations live in lib/system/sync.z, each with its own doc comment; this page is the prose and the worked examples.

The sync unit is for data that threads really do share. A thread's own work is moved to it or borrowed by it (see thread); what several threads use at once is a sync value its owner keeps, and each task holds a view of it -- a .view field. Views coexist, so any number of tasks may hold one; the owner can neither drop nor move it while a task that views it lives. What may change through a shared view is exactly what the type does atomically or under its own lock.

2. Atomics

  • AtomicI32, AtomicI64, AtomicU32, AtomicU64 -- names for Atomic t over each integer type every target updates in one instruction: load, store, exchange, compareExchange, fetchAdd and fetchSub. Arithmetic wraps.
  • AtomicBool -- load, store, exchange, compareExchange.
  • memoryorder -- relaxed, acquire, release, acqRel, seqCst, as C11 and Rust name them. Every operation takes order:, default seqCst -- the one to reach for; the weaker orders are for code that has proved it needs them. A load cannot release and a store cannot acquire: either panics.

exchange is C11's name for Rust's swap, which is a zerolang statement. compareExchange stores new only if the atomic holds current, and answers what it held -- so it stored exactly when the answer is current:

  # Adder -- adds to a counter it shares
  Adder: class {
      # the counter every Adder shares
      total: sync.AtomicI64.view
  } as {
      task: thread.Task
      call: function {:this} is {
          i: 0.i64
          for i < 1000 loop {
              this.total.fetchAdd value: 1
              i = i + 1
          }
      }
  }

  main: function is {
      total: sync.AtomicI64.create value: 0
      {
          a: thread.spawn task: (Adder :total)
          b: thread.spawn task: (Adder :total)
      }
      print "total \{total.load}"
      seen: total.compareExchange current: 2000 new: 0
      print "it held \{seen}, now \{total.load}"
  }

3. Locks

  • Mutex T -- owns a value one thread at a time reaches. create value: moves the value in; lock waits for the lock and answers a MutexGuard, whose value is the Mutex's value to read and write. Destroying the guard unlocks.
  • RwLock T -- owns a value many threads may read at once, or one write: read answers a ReadGuard (its value is a view), write a WriteGuard (its value writes). A writer waits for every reader.

The value is reached only through a guard, so it is never touched unlocked, and the lock model keeps the rest straight: a guard keeps its Mutex (the Mutex cannot be dropped or moved while one lives), value holds the guard for as long as what it answered lives, and a read guard's value cannot be written. T is a reference type (AnyRef); wrap a plain value in a class.

  # Filler -- appends to a list it shares
  Filler: class {
      # the list every Filler shares
      m: (sync.Mutex (ListVal i64)).view
  } as {
      task: thread.Task
      call: function {:this} is {
          i: 0.i64
          for i < 100 loop {
              g: this.m.lock
              g.value.append i
              i = i + 1
          }
      }
  }

  main: function is {
      m: (sync.Mutex (ListVal i64)).create value: ListVal i64
      {
          a: thread.spawn task: (Filler :m)
          b: thread.spawn task: (Filler :m)
      }
      g: m.lock
      print "\{g.value.length} appended"
  }

4. Waiting

  • Condvar -- where a thread waits for a condition another makes true. Holding a Mutex's guard, the waiter calls g.wait cond: cv: it unlocks while it waits and locks again before it returns. g.waitTimeout cond: cv ms: 50 gives up after the time and answers whether it did. The thread that changes the value under the lock calls notifyOne or notifyAll. A wait may return with nothing notified, so the waiter checks its condition in a loop.
  • Barrier -- create count: n; each wait returns once n threads have called it, and answers whether this thread is the round's leader (exactly one is). The barrier is then ready for the next round.
  # Slot -- a value and whether it is set
  Slot: class {
      # whether `value` is set
      ready: bool
      # the value
      value: i64
  }

  # Setter -- sets the slot, then wakes the waiter
  Setter: class {
      # the slot, under its lock
      m: (sync.Mutex Slot).view
      # where the waiter waits
      cv: sync.Condvar.view
  } as {
      task: thread.Task
      call: function {:this} is {
          {
              g: this.m.lock
              with s: g.value do {
                  s.value = 7
                  s.ready = true
              }
          }
          this.cv.notifyAll
      }
  }

  main: function is {
      m: (sync.Mutex Slot).create value: (Slot ready: false value: 0)
      cv: sync.Condvar.create
      h: thread.spawn task: (Setter :m :cv)
      g: m.lock
      for g.value.ready.not loop g.wait cond: cv
      print "set to \{g.value.value}"
  }

5. Channels

  • Channel T -- a queue threads send values through. create capacity: n holds at most n values (0, the default, has no limit); send value: moves a value in and waits while the channel is full; receive waits for a value and answers it as an Option T, none once the channel is closed and drained; tryReceive answers none at once when nothing is waiting. close says nothing more will come and wakes every receiver; sending on a closed channel panics. isClosed and capacity read it.
  • ChannelVal t -- the same for a valtype: values are copied in, and receive answers an optionval t.

Each value goes to exactly one receiver, in the order sent. A value travels to another thread, so it may hold no borrow: send refuses one, as a taking argument with nowhere for its locks to go.

  # Producer -- sends numbered messages
  Producer: class {
      # where it sends
      ch: (sync.Channel String).view
  } as {
      task: thread.Task
      call: function {:this} is {
          i: 0.i64
          for i < 3 loop {
              this.ch.send value: "message \{i}"
              i = i + 1
          }
      }
  }

  main: function is {
      ch: (sync.Channel String).create capacity: 1
      {
          p: thread.spawn task: (Producer :ch)
          n: 0.i64
          for n < 3 loop {
              got: ch.receive
              match (got) case some then print got case none then null
              n = n + 1
          }
      }
      ch.close
      print "after close: \{(ch.receive).none}"
  }

6. Building

A program that uses sync links pthread, like one that starts a thread; every class is written from a C template over the shim src/runtime/natives/_Z_THREAD_SHIM.inc (pthreads, or Win32 on Windows).
