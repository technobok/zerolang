1. Overview

The declarations themselves live in lib/system/math.z and its subunits under lib/system/math/, which are the one place they are written; every definition carries its own doc comment, and zls surfaces each on hover. This page is the prose and the worked examples.

The math unit holds numbers past the machine's own. Today that is BigInt, a signed integer of any size, BigRat, a rational of any size, BigFloat, a binary floating-point number of any precision, and the fixed-width integers int and uint of any number of 64-bit words (i256, u256, i512, u512); the fixed decimals follow on the same core.

The core is a port of Go's math/big at commit 577b91f341 (BSD-3-Clause, the license beside it in math/LICENSE-GO); each ported file names the Go file it came from. The algorithms are Go's: Karatsuba multiplication and squaring, Burnikel-Ziegler division, divide-and-conquer conversion to text, windowed and Montgomery exponentiation, Lehmer's GCD, and a Baillie-PSW primality test. Where Go lets a result alias an operand, the port writes into a second list or calls an in-place twin, and the scratch Go takes from a stack is one list sized before the work starts and carved into windows.

main: function is {
    a: math.BigInt from: 9223372036854775807
    b: a * a * a
    print "\{b.string}"
    print "\{(b.text base: 16)}"
    r: math.BigInt.parse text: "-0x_dead_beef" base: 0
    match (r) case ok then print "\{r.string}" case err then print "bad"
}

3. Constants

math.pi, math.e, math.phi (the golden ratio), math.sqrt2, math.sqrtE, math.sqrtPi, math.sqrtPhi, math.ln2, math.log2E (1 / ln2), math.ln10 and math.log10E (1 / ln10) are untyped float constants, written to 70 digits, so each lands in any float type as that type's value nearest the true constant, rounded once: math.pi is the nearest f64 where an f64 is meant, math.pi.f32 the nearest f32, and math.pi.f128 all 113 bits of the nearest f128. Folded with other constants they stay exact until they land: math.pi / 2 is the nearest f64 to half the 70-digit value.

4. BigInt

A BigInt is a sign and a magnitude: negative, and words, the magnitude's 64-bit words least significant first with no leading zero word. Zero is the empty list and is never negative. It is a class: an operator returns a new value, and the accumulator methods change one in place.

4.0.1. Construction

math.BigInt from: x takes an i64. A narrower integer, signed or not, widens to one by itself, and a literal coerces, so math.BigInt from: 5 and from: k for an i8 or a u32 k read the same. A u64 is math.BigInt.fromU64 from: n, and a 128-bit value is read with parse -- (math.BigInt.parse text: v.string base: 10) -- so a program that writes no 128-bit integer needs none, and builds under tcc, which has none.

math.BigInt.parse text: base: reads an optional sign and then digits:

  • base 2 to 62 reads plain digits -- 0-9, a-z, and above 36 A-Z as the digits 36 to 61; up to 36 the cases mean the same
  • base 0 reads a prefix -- 0b, 0o, 0x, or a bare 0 for octal -- and is decimal without one; only base 0 lets _ separate digits

The whole text must be the number. A text with no digit at all answers parseerror.empty; anything else that is not a number in the base, parseerror.invalidDigit. Any other base panics.

.string is the value in decimal and .text base: in base 2 to 62, in the digits parse reads back, a leading - when negative.

4.0.2. Arithmetic

+, - and * are exact. / truncates toward zero and % takes the dividend's sign, as Go's Quo and Rem do: -7 / 2 is -3 and -7 % 2 is -1. Division by zero panics. neg, abs and sign (-1, 0 or 1) read as their names say.

4.0.3. Division

div by: and mod by: are Euclidean, as Go's Div and Mod: the remainder is never negative, so -7 div 2 is -4 and -7 mod 2 is 1.

divide by: mode: answers a BigDivision, the quotient rounded as the roundingmode asks and the remainder with quo * by + rem == this, as Go's Divide:

  • toZero truncates -- the / and % pair
  • toNegativeInf floors, toPositiveInf ceils
  • toNearestEven rounds a half to the even quotient

The two modes an integer division has no use for panic.

4.0.4. Comparison

The comparisons and compare (-1, 0 or 1) order by value. hash agrees with ==, so a BigInt keys a map. copy is a value with its own words.

4.0.5. Conversions

.i64 and .u64 answer converror.outOfRange for a value they cannot hold. .f64 answers the value when an f64 holds it exactly, precisionLoss when it falls between two, and outOfRange past the largest.

4.0.6. Bits

The bitwise operators read a value as two's complement of unbounded width -- a negative value's sign bits run on forever -- as Go's And, Or, Xor, AndNot and Not do: -1 & x is x, and x >> n of a negative x rounds toward negative infinity (-7 >> 1 is -4). bit i: and setBit i: b: read and set a bit of that form. bitLength and trailingZeros measure the magnitude.

4.0.7. Number theory

  • exp y: m: -- this^y mod |m|, in [0, |m|); a zero m is no modulus, and the plain power is 1 for y <= 0. A negative y with a modulus raises the inverse to |y|, and panics when there is none -- where Go answers nil
  • gcd y: -- never negative; gcdExtended y: answers a BigGCD whose cofactors make gcd == this*x + y*y'
  • modInverse n: -- (Option BigInt): the inverse in [0, |n|), or none when the two share a factor
  • sqrt -- the floor of the square root; panics on a negative value
  • jacobi y: -- the Jacobi symbol for an odd y
  • probablyPrime n: -- n rounds of Miller-Rabin and a Baillie-PSW test. A prime always answers true; a composite chosen at random answers true with probability at most 4^-n, and none below 2^64 ever does. The Miller-Rabin bases come from a SplitMix64 generator seeded by the value's low word, where Go uses math/rand: as fixed for a given number, but not Go's. Not for a number an adversary chose
  • BigInt.product from: to: -- every integer from from to to multiplied: 1 for an empty range, 0 for one that holds 0
  • BigInt.binomial n: k: -- the binomial coefficient C(n, k), 0 when k is negative or past n

4.0.8. Accumulators

acc.add x, sub, mul, quo and rem change acc in place -- the forms for a loop that would otherwise build a new value each step.

sum: function {n: u64} out math.BigInt is {
    acc: math.BigInt from: 0
    for each i: n.times loop acc.add (math.BigInt from: i * i)
    return acc
}

5. BigDivision

A quotient and its remainder, as BigInt.divide answers them: quo * divisor + rem is the dividend.

6. BigGCD

A greatest common divisor and its cofactors, as BigInt.gcdExtended answers them: gcd == a*x + b*y, the gcd never negative.

7. BigRat

A BigRat is a quotient num / den of two BigInts, always in lowest terms: den is positive and shares no factor with num, which carries the sign, and an integer has den 1. Equal values therefore have equal parts, and every result is reduced before it is returned. Like BigInt it is a class, and its operators return new values.

main: function is {
    third: math.BigRat.fromFraction num: (math.BigInt from: 1) den: (math.BigInt from: 3)
    sum: third + third + third
    print "\{sum.string} \{third.decimal digits: 5} \{third.roundF64}"
    r: math.BigRat.parse text: "0.1"
    match (r) case ok then print "\{r.string} \{r.roundF64}" case err then print "bad"
}

This prints 1 0.33333 0.333333 and 1/10 0.1.

7.0.1. Rational construction

math.BigRat from: n takes an i64, as BigInt does; fromFraction num: den: reduces any two BigInts, and panics on a zero den; fromInt from: takes a BigInt whole. fromF64 from: answers (Option BigRat): every finite f64 is a rational exactly (0.1 is 3602879701896397/36028797018963968), and an infinity or a NaN is none.

math.BigRat.parse text: reads a fraction "a/b" -- each part decimal or prefixed 0b, 0o or 0x, the divisor unsigned and not zero -- or a number with a radix point and an exponent: "1.5", "-2.5e-3", "0x1.8p4". A decimal mantissa takes a base-10 e or a base-2 p exponent, a hex one p alone (an e is a hex digit), and a leading 0 is decimal, not octal. The whole text must be the number: parseerror.empty when it holds no digit, overflow for an exponent past what is computed, invalidDigit for anything else.

7.0.2. Rational arithmetic

+ - * / are exact; / and inverse panic on a zero divisor. neg, abs and sign mean what they do on BigInt, and isInt answers whether den is 1.

7.0.3. Rational comparison

compare and the six comparisons order by value; == compares the parts, which lowest terms makes the same thing, and hash agrees with it.

7.0.4. Rational floats

roundF64 and roundF32 answer the nearest float, a tie to the even one, and an infinity past the largest; the sign is the value's, a zero's included. f64 and f32 answer that float only when it is the value exactly -- precisionLoss when it lies between two, and outOfRange past the largest -- as BigInt's conversions do. ieeeBits mbits: ebits: is the nearest value in any IEEE 754 binary interchange format -- binary16 is 10 and 5, binary128 112 and 15 -- as its bit pattern, rounded once from the exact quotient (the quotient is taken two bits wider toward zero and made odd when inexact, which leaves the second rounding nothing to get wrong), subnormals kept.

7.0.5. Rational text

.string is "a/b", or "a" for an integer; .fraction is "a/b" always. decimal digits: writes the value with that many digits after the point, the last rounded to nearest with a half away from zero (-2/3 to 4 digits is -0.6667). decimalPrecision answers a decimalprec: how many digits follow the point before the expansion repeats, and whether that many are exact -- 1/4 has 2, exactly, 1/6 has 1, rounded.

8. BigFloat

A BigFloat is a sign, a mantissa of up to prec bits and an exponent -- sign * mantissa * 2^exp with 0.5 <= mantissa < 1 -- or a signed zero, or a signed infinity. Each value carries the precision and the roundingmode its results round to, and the accuracy of the operation that made it: whether that result lies below, at or above the exact one. The exponent is an i32; past it a result is an infinity, below it a zero. There are no NaNs: an operation whose IEEE 754 result would be one -- inf - inf, 0 * inf, 0 / 0, the root of a negative -- panics, as Go's does. At 24 or 53 bits and toNearestEven the operators give what f32 and f64 arithmetic gives, for operands and results those formats hold as normal numbers.

main: function is {
    two: math.BigFloat from: 2.0 prec: 200
    print (two.sqrt.text format: math.floatformat.fixed digits: 40)
    one: math.BigFloat.fromI64 from: 1
    three: math.BigFloat.fromI64 from: 3
    third: math.BigFloat.quotient x: one y: three prec: 24 mode: math.roundingmode.toZero
    print "\{third.string} \{third.acc.below} \{third.roundF32}"
    r: math.BigFloat.parse text: "1e-400" prec: 64
    match (r) case ok then {
        print "\{r.string} \{r.roundF64}"
        print (r.text format: math.floatformat.hex digits: -1)
    } case err then print "bad"
}

This prints 1.4142135623730950488016887242096980785697, 0.3333333135 1 0.333333, 1e-400 0 and 0x1.2bfcfc0f923df5f4p-1329.

8.0.1. Float construction

Every constructor takes prec: and mode:; prec: 0, the default, picks the precision that holds the source exactly -- 53 bits for an f64, 64 for an integer, the larger of 64 and the bit length for a BigInt -- and mode defaults to toNearestEven. A smaller precision rounds by the mode. math.BigFloat from: x takes an f64, and panics on a NaN; fromI64, fromU64 and fromInt take integers; fromRat takes a BigRat, its default precision the larger of its parts' bit lengths and 64. zero and inf make a signed zero and a signed infinity. fromIEEEBits bits: mbits: ebits: reads an IEEE 754 interchange format of mbits stored mantissa bits and an ebits-bit exponent -- binary16 is 10 and 5, binary128 112 and 15 -- exactly, and is none for a NaN.

math.BigFloat.parse text: base: prec: mode: reads an optional sign, then a mantissa with an optional radix point and an optional exponent -- e for a power of 10, p for a power of 2 -- or "Inf" or "inf". Base 0, the default, reads a 0b, 0o or 0x prefix and lets _ separate digits; 2, 8, 10 and 16 read plain digits in that base. A hexadecimal mantissa takes p alone, since e is one of its digits. The value rounds once to prec bits, 0 taking 64. The whole text must be the number: parseerror.empty when it holds no digit, overflow for an exponent past what a BigFloat holds, invalidDigit for anything else.

8.0.2. Float arithmetic

The operators round to the larger operand precision by the left operand's mode. sum, difference, product and quotient take the precision and the mode their result rounds to, prec: 0 again the larger of the operands'. add, sub, mul and quo write the result back into the value, at its own precision and mode: the accumulator form for a loop. sqrt rounds the root to the value's precision and mode, and the root of -0 is -0. neg and abs change only the sign. An exact zero sum is +0 but under toNegativeInf, where it is -0, as IEEE 754 has it; a nonzero over a zero is an infinity.

8.0.3. Float precision

withPrec prec: rounds a copy to that many bits by its mode -- 0 makes a finite value a zero of its sign -- and withMode mode: changes the mode a copy rounds by from then on. minPrec is the fewest bits that hold the value exactly. The acc field reads the accuracy of the operation that made the value; a conversion's accuracy is the sign of converted.compare rhs: x.

8.0.4. Float parts

sign is -1, 0 or 1, with -0 a 0; the negative field is the sign bit, a zero's included. isInf and isInt mean what they say. exponent and mantissa split a value into mantissa * 2^exponent with 0.5 <= |mantissa| < 1; scaleB n: multiplies by 2^n exactly unless the exponent leaves the i32.

8.0.5. Float comparison

compare and the six comparisons order by value: -0 equals 0, and two values of different precisions compare as numbers. There is no hash: equal values may differ in precision and mode, which is what a BigFloat carries besides its value.

8.0.6. Float conversions

.i64, .u64, .f64 and .f32 answer the value only when it is the target exactly: precisionLoss for a fraction or a value between two floats, outOfRange past the target -- an infinity included for the integers. roundF64 and roundF32 answer the nearest float, a tie to the even one, with subnormals kept; a value too small is a zero of its sign and one too large an infinity. ieeeBits mbits: ebits: is the same rounding into any IEEE 754 binary interchange format, as its bit pattern. truncInt is the integer toward zero, none for an infinity, and rat the value exactly as a BigRat, none for an infinity.

8.0.7. Float text

.string is the value in general format with 10 digits. text format: digits: spells it in a floatformat: exponent (-d.dddde+dd), fixed (-dddd.dddd), general (the exponent form for exponents below -4 or at least the digit count, the fixed one otherwise), their upper-case forms, hex (-0x1.dddp+dd), hexFraction (-0x.dddp+dd) and binary (-ddddp+dd, a decimal mantissa of prec bits). The digit count is the digits after the point for exponent, fixed and hex, and the digits in all for general; a negative count spells the fewest decimal digits that read back as this value at its precision. Decimal digits round to nearest even. An infinity is "+Inf" or "-Inf". Go's Format and Scan, the fmt package's verbs and flags, have no counterpart here.

9. decimalprec

The digits a rational's decimal expansion has before it repeats, and whether that many spell it exactly, as BigRat.decimalPrecision answers them.

10. roundingmode

How a result between two representable values is chosen: the nearer with a tie to the even one (toNearestEven) or away from zero (toNearestAway), toward zero, away from zero, or toward either infinity. Every math type that rounds takes it.

11. accuracy

How a rounded result compares to the exact value: below, exact or above, as a BigFloat's acc reports it.

12. floatformat

How BigFloat.text spells a value, Go's format letters by name: exponent 'e', exponentUpper 'E', fixed 'f', general 'g', generalUpper 'G', hex 'x', hexFraction 'p' and binary 'b'.

13. Fixed-width integers

(math.int words: N) and (math.uint words: N) hold N 64-bit words, least significant first, in two's complement: a signed or unsigned integer of 64*N bits. They are records -- valtypes -- so they sit in other records, in variants and in arrays as plain data, and copy as values. math.i256 and math.u256 name the 4-word instances, math.i512 and math.u512 the 8-word ones; any other width is written out, as (math.int words: 3).

Their arithmetic is the i64 family's. +, -, * and neg wrap modulo 2^(64*N); / truncates toward zero and % takes the dividend's sign, a zero divisor panics, and the most negative int divided by -1 wraps to itself. << and >> take a u64 count: past the width a left shift gives 0 and a right shift 0, or -1 for a negative int, whose right shift copies the sign in.

create from: takes an i64 for int and a u64 for uint, and defaults to 0, so a bare math.i256 is zero. fromBig from: reads a BigInt and parse text: base: reads text as BigInt.parse does; both answer a resultval -- outOfRange, or parseerror.overflow -- when the value does not fit, rather than wrapping it. Out, big is the exact BigInt, string and text base: are its text, and i64, u64 and f64 answer a resultval as the BigInt conversions do.

==, compare and the order operators compare the values; hash agrees with ==, so either type keys a map or set over value keys, such as MapVR k: math.i256 V: String.

main: function is {
    a: math.i256 from: -1
    b: math.u256.parse text: "0xffff_ffff_ffff_ffff_ffff" base: 0
    match b case ok then print "\{(b * b).string}" case err then print "bad"
    print "\{(a >> 255).string} \{(a.neg << 255).string}"
}

The word loops are math's C kernels run over the limbs' own windows, so a fixed-width integer costs no allocation for +, -, *, the bit operators and the shifts; /, %, the text and the conversions through BigInt do allocate.

14. Performance and toolchains

The loops every operation rests on -- add, subtract, shift and multiply-and-add over runs of 64-bit words -- are C, in src/runtime/natives/_Z_MATH_ARITH.inc, a port of Go's portable loops; the rest of math is zerolang. The loops step through the system word primitives, and those take a C compiler's fast forms where it has them: unsigned __int128 for the two-word product and __builtin_addcll / __builtin_subcll for a carry chain, which gcc and clang lower to mul, adc and sbb on x86-64 and to umulh and adcs on aarch64. Elsewhere the primitives are portable C -- the product in four 32-bit pieces, the carry by comparison. Both give the same words, and the corpus holds both to the same goldens.

tcc always takes the portable forms: it has no __int128 and no carry builtins, and its assembler knows no MULX, ADCX or ADOX. math is as correct under tcc and slower; build with gcc or clang, --release, for speed.

make bench-math times each operation at sizes from 1 to 100,000 words in three builds: gcc with the fast forms, gcc with -DZ_WORD_PORTABLE forcing the portable ones, and tcc. make test-math-arm64 builds the math corpus with --target aarch64-linux-gnu and runs it under qemu.
