1. Overview

The declarations themselves live in lib/system/path.z, which is the one place they are written, each with its doc comment. This page is the prose.

path handles file system paths as the operating system the program is built for spells them, as Go's path/filepath does. On Windows \ is the separator and / is read as one too, and a path may begin with a drive (C:\), a share (\\server\share\) or the verbatim prefix (\\?\); elsewhere / is the only separator and the only root. join and clean write the native separator, so a path a program composes is one the system and its users read as their own. Every function is pure text: none asks the file system. The system the build is for is a compile-time answer (z.build.os), so a cross build for Windows composes Windows paths.

2. Index

  • separator -- function out String: \ on Windows, / elsewhere
  • listSeparator -- function out String: what separates a list of paths, as PATH spells it: ; on Windows, : elsewhere
  • isSeparator -- function {b: u8} out bool
  • rootLength / root -- the root's bytes, and the root with native separators
  • isAbsolute -- function {p: StringView} out bool
  • clean -- function {p: StringView} out String
  • join -- function {a: StringView b: StringView} out String
  • dirname / baseName -- function {p: StringView} out String
  • toSlash -- function {p: StringView} out String: p with / for each separator -- on Windows each \ becomes /, elsewhere p as written (Go's filepath.ToSlash). For text spelled with / whatever the system: a URI, a key, a golden.

3. Roots and absolute paths

A root is what a path is anchored to. On POSIX it is /. On Windows it is a drive with its separator (C:\), a share (\\server\share\), a verbatim or device path (\\?\C:\, \\?\UNC\server\share\), a drive alone (C:, that drive's current directory) or a separator alone (\, the current drive's root). isAbsolute is true when a path names the same place from any working directory: on Windows that rules out C:x and \x, which depend on the current drive and its directory.

4. Clean, join, dirname and baseName

clean answers the shortest path naming the same place by text alone: one native separator between components, . components dropped, each .. taking the component before it (never climbing past a root), no trailing separator, and . for an empty result.

join puts one native separator between its two parts and cleans the result; an absolute second part stands alone, and an empty part contributes nothing.

dirname is the path without its last component, cleaned: the root for a path directly in it, . for a relative path of one component. baseName is the last component, trailing separators ignored, and "" when there is none (an empty path, or a root alone).

  p: path.join a: "build" b: "out/zc"
  print p                  # build/out/zc, or build\out\zc on Windows
  print (path.dirname p: p.stringView)   # build/out
  print (path.baseName p: p.stringView)  # zc
