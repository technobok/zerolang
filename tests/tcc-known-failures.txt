# Programs the vendored tcc cannot build, and the stage each one fails at.
# Read by `make test-tcc`. One line per program: `<name> (<stage>)`.
#
#   (zc)  the declaring unit guards itself: zc reports E0601 from the unit's
#         own `require:` block, naming the type and the toolchain, before any
#         C is written. This is the finished state.
#   (cc)  no guarded unit yet: tcc rejects the emitted C with a parse error
#         naming a type the program never wrote, in a temp file zc has already
#         deleted. This is what a `require:` block exists to replace.
#
# Moving a line from (cc) to (zc) is the work: give the type a unit with a
# `require:` block, the way f128 lives in system's quadfloat subunit.
# The gate fails on movement in EITHER direction, so that split is a
# deliberate edit here rather than a silent change in what tcc accepts.
#
# Every line below is now (zc): each of these programs is turned away by the
# unit that declares the type it uses, naming the type and the toolchain,
# before any C is written. A new (cc) line is a type that has acquired no
# unit to speak for it.

# __float128: system's quadfloat subunit carries the guard.
float_widths (zc)
float_mod (zc)

# __int128: system's wideint subunit carries the guard.
bare_zero_scalar (zc)
int128_print (zc)
interp_i128_method (zc)

# These two are error fixtures, not run cases, and the stage names the KIND
# that failed rather than a build phase. Each pins a literal-width E0300 and
# needs a genuinely wider type to pin it, so each writes i128 -- which means
# that under tcc each collects the wideint guard as a SECOND error and no longer
# matches a golden written for one. The E0300 they exist to pin still matches
# exactly; what they have stopped being is buildable, which is the truth.
comparison_literal_width (error)
binop_literal_width (error)

# This one runs under --eager, which resolves every definition of every unit
# rather than the ones the program demands -- so it reaches the gated numeric
# units and collects their guards the same way the two above do. It pins the
# unit-constant SHAPE diagnostic, which fires for definitions nothing
# references and therefore belongs to the eager tier; the toolchain is
# incidental to what it checks.
unit_constant_construction (error)
