# known-leaks.txt -- programs expected to still hold memory when they exit,
# per compiler family, as "<name> (<kind>)". A program listed here that comes
# up CLEAN fails the ratchet: the entry has to be deleted in the same commit as
# whatever fixed it. A program NOT listed here that leaks fails outright.
#
# Keyed by family because the two sanitizers do not measure the same thing.
# ASan reports what is definitely LOST -- unreachable at exit. tcc's bounds
# checker, under TCC_BOUNDS_PRINT_HEAP, prints every block still LIVE at exit,
# reachable or not. The zerolang invariant is the stricter one (`make
# perf-strict` asserts allocs == frees), so tcc's reading is the more useful of
# the two; it is also why a row can be right for tcc and wrong for gcc.
#
# os_basics ends in `os.exit`, which terminates immediately and by design skips
# zerolang's destructors -- the example says so in its own comment, and it is
# demonstrating exactly that. Its four blocks (argv, two env strings) are still
# reachable, so ASan is silent and the bounds checker is not. Verified with
# valgrind: 9 allocs, 5 frees, 0 definitely lost.
os_basics (tcc)
